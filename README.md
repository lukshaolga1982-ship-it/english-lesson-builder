# Smart Lesson

Конструктор методически связанных планов-конспектов уроков английского языка для учителей Республики Беларусь.

## Ссылка на электронный учебник

На шаге «Основа урока» под выбором учебника добавлена кнопка **e-padruchnik**. Она открывает официальный каталог электронных учебников Республики Беларусь в новой вкладке, чтобы учитель мог быстро сверить часть и страницы перед генерацией плана.


## Что изменено в версии 0.3

- добавлено отдельное **методическое ядро** (`src/methodology.js`);
- урок проверяется по четырём признакам логики: **целенаправленность, целостность, динамика, связность**;
- у каждого этапа теперь есть:
  - методическая функция;
  - конкретный результат этапа;
  - **логический мостик к следующему этапу**;
- мостики строятся по принципу: **результат → вопрос/дефицит → следующее действие**;
- учитывается последовательность упражнений от опоры и тренировки к более самостоятельному речевому действию;
- добавлены методические траектории для:
  - диалогической речи;
  - монологической речи;
  - аудирования;
  - чтения;
  - письменной речи;
  - лексики;
  - грамматики;
- после генерации предлагаются **3 варианта**:
  - креативного начала урока;
  - двигательной паузы / физкультминутки;
  - рефлексии;
- любой из вариантов можно применить к готовому плану одной кнопкой;
- рефлексия привязывается к цели и критериям успеха;
- добавлена методическая самопроверка готового плана;
- логические мостики и результаты этапов экспортируются в Word;
- физкультминутка больше не заблокирована как обязательная — её можно отключить.

## Методическая база

Логика генератора собрана на основе материалов, предоставленных для проекта:

- О. А. Соловьёва, **«Методика преподавания иностранных языков»**, МГЛУ, 2024;
- учебные программы Республики Беларусь по учебному предмету «Иностранный язык» для V–XI классов;
- «Канструктар урокаў» как банк методических приёмов;
- «Конструктор урока для технологических карт» как дополнительный банк вариантов начала, закрепления и рефлексии.

PDF/DOCX-источники не нужно добавлять в публичный GitHub-репозиторий: в проект вынесены только структурированные методические правила и названия/описания приёмов, необходимые генератору.

Подробнее: [`METHODOLOGY.md`](./METHODOLOGY.md).

## Как устроена генерация

```text
Параметры учителя
        ↓
Методическое ядро
        ↓
Цель + критерии успеха
        ↓
Последовательность упражнений
        ↓
Результат каждого этапа
        ↓
Логические мостики между этапами
        ↓
Коммуникативная кульминация
        ↓
Рефлексия по цели
        ↓
Методическая самопроверка
```

## Запуск локально

Нужен Node.js 20+.

```bash
npm install
npm run dev
```

## Firebase Authentication

В Firebase Console для проекта `english-lesson-builder`:

1. **Authentication → Sign-in method → Google → Enable**.
2. В **Authentication → Settings → Authorized domains** добавьте:
   - `lukshaolga1982-ship-it.github.io`
   - `localhost`.

Правила находятся в `firestore.rules`.

```bash
npm install -g firebase-tools
firebase login
firebase use english-lesson-builder
firebase deploy --only firestore:rules
```

### Важно

Основное новое методическое ядро передаётся моделью **из фронтенда (`src/api.js` + `src/methodology.js`)**, поэтому публикация новой версии сайта на GitHub Pages уже включает новую методическую логику.

`cloudflare-worker.js` тоже обновлён и содержит те же требования к связности. Чтобы обновить именно серверный system prompt, этот файл нужно отдельно скопировать/задеплоить в Cloudflare Worker. GitHub Pages сам Worker не разворачивает.

## GitHub Pages

Загрузите **всё содержимое корневой папки проекта** в репозиторий:

`https://github.com/lukshaolga1982-ship-it/english-lesson-builder`

## Тексты страниц учебников

Структура Firestore:

```text
textbooks/{bookId}/pages/{pageNumber}
```

Пример:

```text
textbooks/demchenko-6-2026/pages/23
```

Документ страницы:

```json
{
  "text": "Текст страницы 23..."
}
```

Важно: текущий Cloudflare Worker получает от браузера сформированный prompt. Если требуется фактически подгружать текст выбранных страниц непосредственно на сервере, нужно отдельно перенести/реализовать загрузку Firestore-контекста в Worker. Генератору уже запрещено утверждать, что он видел страницы, если их текст фактически не был передан.

## Проверка перед публикацией

```bash
npm install
npm run build
```

После публикации рекомендуется сделать тестовый урок и проверить:

1. сумма минут равна длительности урока;
2. у каждого этапа, кроме последнего, есть содержательный мостик;
3. результат предыдущего этапа используется в следующем;
4. ведущая речевая деятельность действительно является кульминацией урока;
5. доступны 3 варианта начала, двигательной паузы и рефлексии;
6. выбранный альтернативный вариант корректно подставляется в этап;
7. Word-файл содержит результаты этапов и логические мостики.
