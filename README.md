# Smart Lesson

Конструктор методически связанных планов-конспектов уроков английского языка для учителей Республики Беларусь.

## Версия 0.5 — автоматическая работа со страницами учебника

Теперь **не нужно заранее скачивать все учебники и вручную загружать страницы в Firestore**.

Сценарий работы:

```text
Учитель выбирает учебник и вводит страницы
        ↓
Сайт проверяет личный кэш Firestore
        ↓
Если страниц нет — Worker ищет электронную версию учебника
        ↓
PDF безопасно передаётся браузеру через Worker
        ↓
PDF.js извлекает текст только нужных страниц
        ↓
Текст сохраняется в users/{uid}/textbookCache
        ↓
Реальный текст страниц передаётся Groq
        ↓
План строится с опорой на упражнения, тексты, лексику и грамматику выбранного разворота
```

### Что видит учитель

На шаге **«Основа урока»**:

1. выбирает учебник;
2. указывает часть и страницы, например `38–39`;
3. может нажать **«Получить страницы»** для предварительной проверки;
4. либо сразу нажимает генерацию — сайт сам попробует получить страницы;
5. кнопка **e-padruchnik** остаётся рядом для визуальной сверки учебника;
6. ручная вставка текста остаётся только резервным вариантом.

Если страница уже использовалась раньше, повторно скачивать PDF не нужно: текст берётся из личного кэша Firestore.

### Источники электронных версий

Worker сначала пытается определить электронную версию через официальный каталог `e-padruchnik.adu.by`. Для нескольких проверенных более ранних изданий настроены стабильные резервные зеркала. Для новых изданий Worker **не подменяет книгу старым похожим учебником**: если конкретное издание надёжно не найдено, интерфейс сообщит об этом и предложит резервную ручную вставку текста.

## Что изменено в методической части

- отдельное **методическое ядро** (`src/methodology.js`);
- урок проверяется по четырём признакам логики: **целенаправленность, целостность, динамика, связность**;
- у каждого этапа есть методическая функция и конкретный результат;
- между соседними этапами создаётся **логический мостик**;
- мостики строятся по принципу: **результат → вопрос/дефицит → следующее действие**;
- упражнения выстраиваются от опоры и тренировки к самостоятельному речевому действию;
- есть траектории для диалогической речи, монологической речи, аудирования, чтения, письменной речи, лексики и грамматики;
- после генерации предлагаются по 3 варианта креативного начала, двигательной паузы и рефлексии;
- рефлексия связывается с целью и критериями успеха;
- логические мостики и результаты этапов экспортируются в Word.

Подробнее: [`METHODOLOGY.md`](./METHODOLOGY.md).

## Firestore

Предварительно загружать учебники больше не требуется.

Автоматически извлечённые страницы сохраняются только в личном пространстве пользователя:

```text
users/{uid}/textbookCache/{bookId__part-X__page-Y}
```

В документе хранятся текст страницы, номер печатной/PDF-страницы и сведения об источнике.

Общая библиотека `textbooks/{bookId}/pages/{pageNumber}` всё ещё поддерживается в режиме чтения для обратной совместимости.

### После обновления обязательно опубликовать новые правила

Через Firebase Console:

1. **Firestore Database → Rules**;
2. заменить текущие правила содержимым файла `firestore.rules`;
3. нажать **Publish**.

Либо через CLI:

```bash
firebase deploy --only firestore:rules
```

## Cloudflare Worker

Фронтенд использует Worker:

`https://proud-surf-1244.lukshaolga1982.workers.dev`

Bindings остаются прежними:

- Secret `GROQ_API_KEY`;
- KV binding `USAGE_LIMITS`.

Новый binding для учебников не требуется. `USAGE_LIMITS` также используется для кратковременного кэша найденных URL электронных версий.

### После обновления Worker нужно заменить обязательно

GitHub Pages **не разворачивает Worker автоматически**. Поэтому файл `cloudflare-worker.js` из этой версии нужно отдельно вставить в Cloudflare:

1. **Cloudflare → Workers & Pages**;
2. открыть текущий Worker;
3. **Edit code**;
4. заменить весь код содержимым `cloudflare-worker.js`;
5. **Deploy**.

Новые endpoints Worker:

```text
POST /textbook-source
POST /textbook-pdf
```

Они работают только для вошедшего Firebase-пользователя.

## Как проверить после публикации

1. войти через Google;
2. выбрать поддерживаемый учебник;
3. указать часть, если книга состоит из двух частей;
4. ввести страницы, например `38–39`;
5. нажать **«Получить страницы»**;
6. дождаться зелёного статуса `Готово`;
7. сгенерировать урок;
8. в готовом плане проверить блок **«Опора на учебник»**.

При повторном запросе тех же страниц сообщение должно указывать, что страницы уже сохранены и повторная загрузка не потребовалась.

## Ограничения автоматического режима

- Для учебника, введённого вручную (`custom-*`), автоматическое получение пока недоступно.
- PDF должен содержать текстовый слой. Если это только скан-картинки, браузер не сможет корректно извлечь текст без OCR.
- Структура внешнего каталога электронных учебников может меняться. Если конкретное новое издание перестанет автоматически определяться, сайт не должен подменять его старой книгой — будет показан резервный ручной вариант.
- За один запрос извлекается не более 24 страниц; это защищает браузер и запрос к модели от слишком большого объёма.

## v0.6 — фото страниц и загрузка PDF учебника

На шаге «Основа урока» теперь доступны три способа передать содержание учебника:

1. автоматическое получение электронной версии;
2. загрузка фото страниц (JPG/PNG/WEBP) с OCR через Groq vision;
3. загрузка PDF учебника с компьютера — браузер извлекает только указанные печатные страницы.

PDF-файл целиком в Firestore не сохраняется. В личном `users/{uid}/textbookCache` сохраняется только извлечённый текст нужных страниц. Фото также не сохраняются в Firestore: после OCR сохраняется только распознанный текст, если удалось однозначно сопоставить одно фото одной странице.

Для OCR необходимо обновить Cloudflare Worker из этого же репозитория: появился endpoint `/ocr-textbook-images`. Секрет `GROQ_API_KEY` остаётся прежним.
